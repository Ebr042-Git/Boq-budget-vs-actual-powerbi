# BOQ Budget vs Actual: Power BI cost-control report

A two-page Power BI report that answers one question for a project manager:
**which trades and projects are running over their Bill of Quantities (BOQ) budget, and why?**

> All data is **synthetic** (generated by the SQL script in `sql/`). No real company or client data is used.

## What the report shows

- **Total budget AED 199.6M vs actual AED 203.5M**, an overrun of **AED 3.90M (1.95%)**.
- **All 8 trades are over budget.** HVAC and Plumbing are highest in percentage (2.28%); Plumbing is highest in amount (AED 592K).
- **Worst project:** Oasis School Campus at 2.45%. **Best:** Creek Office Park at 1.40%.
- A dashed line on the overrun charts marks the portfolio average (1.95%), so each bar reads as above or below it at a glance. On the Project Detail page it marks the selected project's own overall overrun.

## How the report is organised

| Page | Question it answers |
|---|---|
| **Executive Overview** | *What* is over budget? KPIs, overrun by trade, overrun by project, cost trend by month, trade table. |
| **Project Detail** (hidden, reached by drill-through) | *Why*? Right-click a project to see its trades, monthly cost and the Top 10 items causing the overrun. |

Design choices:

- **Ledger look:** white cards on a light grey page, one navy and blue accent, red only for "over budget". See `theme/BOQ_Ledger_Navy.json`.
- Bars use colour with meaning: red to amber by overrun %, navy to light blue by cost. No decoration.
- Slicers, KPIs and charts sit on a fixed 1920 x 1080 grid (36 px margin, 24 px gap) so everything aligns.

## Data model

Star schema built on SQL Server (`sql/BOQ_Demo_Setup.sql`):

- **Dimensions:** `DimDate`, `DimProject`, `DimTrade`, `DimItem`, `DimVendor`
- **Facts:** `FactBOQ` (budget, one row per project and item), `FactActual` (monthly cost entries), `FactQuotation` (vendor quotes)
- Dimensions filter facts one-to-many. Facts are never joined to each other, because they have different grains and a direct join would double-count the budget.
- `DimTrade` joins `DimItem` (a small snowflake), so a Trade slicer reaches the facts through the item.

## DAX

Five measures, all in `_Measures`. Full code and reasoning: [`dax/DAX_measures.md`](dax/DAX_measures.md).

```DAX
Budget Amount = IF ( ISFILTERED ( DimDate ), BLANK (), SUM ( FactBOQ[BudgetAmount] ) )
Actual Amount = SUM ( FactActual[ActualAmount] )
Variance      = IF ( ISBLANK ( [Budget Amount] ), BLANK (), [Actual Amount] - [Budget Amount] )
Variance%     = DIVIDE ( [Variance], [Budget Amount] )
```

## Known limitation (stated openly)

Budget has **no date**: it is set per project and item, once. So there is no month-by-month
Budget vs Actual comparison. The budget measure returns BLANK under a date filter instead of
repeating the full budget in every month, which would be a wrong number.
In a real project I would ask the data owner to add a budget phasing date.

## How to rebuild it

1. Run `sql/BOQ_Demo_Setup.sql` in SQL Server (it creates the `BOQ_Demo` database and loads the synthetic data).
2. In Power BI Desktop, connect to `BOQ_Demo` (Import mode) and load the 8 tables.
3. Mark `DimDate[Date]` as the date table, sort `MonthName` by `MonthNo`, and set Year/keys to "Don't summarize".
4. Create the measures from `dax/DAX_measures.md`.
5. Apply `theme/BOQ_Ledger_Navy.json` (View > Themes > Browse for themes).
